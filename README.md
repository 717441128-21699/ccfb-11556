# logpipe — 自研日志采集系统

替代"rsync 每小时拉一次"的实时日志采集:每台机器跑一个采集代理,日志实时推送到中心,
中心带 Web 监控页。纯 Python 标准库,无第三方依赖,Windows / Linux 均可运行。

```
logpipe/
  common.py    共享工具:多行归并、共享句柄打开、文件身份标识
  agent.py     采集代理(每台机器一个)
  central.py   中心端:接收 / 去重 / SQLite 存储 / Web 监控
stress_test.py 压测:30 台机器 + 频繁轮转 + 随机杀代理 + 随机断网 + 逐行核对
```

## 快速开始

```bash
# 中心端(默认 :8765)
python -m logpipe.central --port 8765 --db central.db

# 打开 Web 监控: http://中心地址:8765
# 在"采集配置"页下发配置,例如:
# {"default": {"multiline": "^\\d{4}-\\d{2}-\\d{2}"},
#  "hosts": {"web-01": {"globs": ["/var/log/app/*.log*"]}}}

# 每台机器跑代理(配置也可只写本地文件兜底)
python -m logpipe.agent --host web-01 --server http://中心地址:8765 \
    --workdir /var/lib/logpipe --config agent.json

# 压测(30 台虚拟机等价验证)
python stress_test.py --hosts 30 --duration 90
```

## 七项需求的实现方式

1. **通配路径盯文件,新文件自动加入** — 代理每 0.25s 按 `globs` 扫描,
   新出现的文件自动开跟踪;配置由中心统一下发(代理每 3s 拉取,本地有缓存兜底)。

2. **轮转不丢不重** — 文件身份 = `(dev, inode, 创建时间, 代际号)`:
   - *改名轮转*:句柄跟着 inode 走,旧文件读到 EOF;改名后的归档仍被通配匹配,
     重启后也能按身份续读;
   - *截断 / copytruncate*:`文件大小 < 已读位置` 直接判出;截断后立刻重写会绕过
     这个检查,所以再校验"已读位置前 64 字节指纹",对不上即判定内容被换,
     老一代封档、同 inode 开新一代(代际号 +1),新旧数据都完整。

3. **断点续传** — 读取位点持久化在本地 SQLite;**记录写入发送缓冲(spool)与
   位点推进在同一个事务里提交**,进程在任意时刻被杀状态都一致:已入 spool 的
   重启后补发,未入 spool 的按位点重读。同名新文件靠 inode+创建时间区分。

4. **多行归并** — 不匹配首行正则(默认时间戳开头)的行并入上一条;
   下一条首行到达或空闲超时(默认 1s)时封口。位点始终指在记录边界,
   崩溃重读能重新拼出同一条记录。

5. **本地磁盘缓冲** — 中心不可达时记录落 SQLite spool;超过 `spool_max_bytes`
   后反压(暂停读取),不会无限制涨磁盘。

6. **三元组去重** — 每条记录带 `(host, file_id, offset)`,中心以此为主键
   `INSERT OR IGNORE`;补发、重发、重启重读产生的重复都被拦下(监控页可见拦截数)。

7. **断网顺序补发** — spool 即有序队列,发送线程按主键顺序批量 POST,
   中心确认后才删除;断网期间堆积,恢复后按原顺序补发。

## 丢失排查原理(中心 Web 页)

代理心跳上报每个文件代际的读取位点与大小;中心把已收记录的 `[offset, offset+blen)`
区间合并,比对出**缺口区间**(应有却没有的字节范围)与**滞后**(文件大小 − 已收)。
一切正常时该页显示"全部文件区间完整"。

## 压测(stress_test.py)

- 30 个写入线程模拟应用:每台每 10–60ms 写 1–15 条(30% 带多行堆栈),
  按 4–16KB 轮转(rename / truncate / copytruncate 混合),随机开新日志文件;
- 混沌:每 4–9s 随机杀一个代理(2–6s 后拉起)或断网 2–6s;
- 结束后把中心存储与源端流水账**逐条核对**(记录多重集 + 行数),并检查缺口页。

最近一次 30 台 × 60s 结果:**114,300 条记录 / 319,647 行,1,935 次轮转,
杀代理 6 次,断网 2 次,全部一致,一行不差**。

## 已知边界(任何采集器都一样)

- 文件被**截断/删除时采集代理还没读到**的内容无法挽回 —— 这是物理限制,
  不是实现缺陷。压测里写入线程做破坏性轮转前会确认代理已追平
  (追不上则跳过该次),rename 轮转无此限制。
- 文件关闭(空闲)后被截断并重写到**完全相同的大小**且 mtime 未变,理论上
  可能漏检;运行中的文件靠 64 字节指纹兜底,实际可忽略。
